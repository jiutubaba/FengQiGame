# 游戏客户端协议

更新时间：2026-08-07

面向接入方的简要说明见 `docs/游戏客户端接入.md`；可直接移交游戏项目的完整协议见 `docs/FQ游戏服务器接口技术说明.md`。本文件只维护开发合约。

## 身份边界

- 游戏端专属接口统一挂载在 `/api/fq`，请求携带 `FQ-Map-Key`；服务端用哈希查找有效 API Key，并写入最近使用时间。
- Key 固定地图和权限；数据库保存认证哈希、前缀和 AES-256-GCM 密文。具备当前地图 `api_keys.manage` 权限的后台用户可通过显式详情请求查看完整 Token，列表接口仍只返回前缀，查看动作写入审计。
- 每个接口使用独立 `game.*` 权限，权限清单由源码生成到 `.ai/generated/code-facts.md`。

## 写入语义

- 玩家存档按 `map_id + player_uid` 唯一保存；地图全局存档按 `map_id` 唯一保存。
- 存档保存提交完整 JSON 快照、`expectedRevision` 和以 `FQ-` 开头的 `requestId`。版本匹配时 revision 加一；最近一次相同请求可安全重放，相同 ID 改写内容或旧版本覆盖均返回 409。
- 开局 `POST /api/fq/bootstrap` 的 24 人是通用接口防滥用上限，客户端只提交本局实际参与者；接口固定返回当前地图不超过 256 KiB 的文本 `preloadCode`。空字符串表示无预加载操作；未创建记录返回 revision 0 和空对象，存档封禁玩家不下发已有快照且不能写入。
- 玩家资料通过单次请求批量上报最多 24 人，按 `map_id + uid` upsert，并刷新最后活跃时间。
- 自动指标使用 `sessions/start`、`sessions/heartbeat`、`sessions/end` 三类原始事件；请求只提交完整 `sessionId` 和最多 24 个去重 UID，地图、日期和时间分别取 API Key 绑定值与服务端北京时间。相同会话事件可安全重放，重复开始/结束固定复用首次事件时间，已结束会话的迟到心跳不写活跃事实。
- 存在自动会话数据时，后台从统计纪元首日实时聚合累计、在线、局数、新增、活跃、流失、回流、三项留存和复玩率，在线以未结束且 120 秒内收到玩家心跳为准；比率同时返回分子和分母，旧按日指标 upsert 仅作没有自动会话数据时的快照兼容入口，省略日期时也使用北京时间。
- 排行榜批量上报最多 500 条；所有榜单通过独立每日采集记录按 FQ 服务器北京时间自然日只接受每个 UID 当日首次提交，后台删除候选条目不会允许同日重报。`latest` 榜使用每日首次样本，`best` 榜只在该样本严格更优时更新最佳成绩。
- 排行榜读取只返回最新人工发布快照的前 100 名和快照内指定 UID 名次，同时返回当日已采集 UID；没有快照时明确返回未发布，不回退实时榜。
- 风险事件使用客户端 `eventId` 作为幂等键；相同地图和事件键重试不重复创建。

## 可靠投递

- 消息和礼包通过 `POST /api/fq/deliveries/query` 一次批量读取最多 24 个 UID。接口始终要求 `game.gifts.read`；只有 `includeMessages` 为 `true` 时才额外要求 `game.messages.read` 并查询消息。响应仍按请求 UID 归位。
- 消息遵循“游戏内写入成功 → ACK”，未 ACK 记录可以再次返回，客户端必须按消息 ID 自身幂等。礼包资格按玩家最新上报的完整昵称精确匹配；同名多 UID 的同一礼包取最大正数值，不写档、不累计、不 ACK。
- ACK 必须核对 UID 和地图，不能确认其他玩家或其他 Key 范围的记录。

## 响应与日志

- 成功返回 `{ success: true }` 或 `{ success: true, data }`；失败返回 `{ success: false, error: { code, message }, requestId }`。写接口只返回客户端推进状态所需的最小确认；存档保存只回新 revision，玩家上报、指标、榜单写入和消息 ACK 不回显已提交正文或服务端时间。
- 客户端可以记录 `requestId`、状态码和业务错误码，不得记录完整 Key、密码或玩家敏感资料。

## 《沧澜》接入状态

- 《沧澜》源码已实现独立 `FQHttpClient`、`FQServer`、启动门闩、原始 JSON 快照与 revision 处理，不再使用旧 `/war3/` 链。
- 本机私有 `FQPrivateConfig.lua` 由地图项目自行维护；实现状态不能代替实际联调结果。
- 《沧澜》启动链使用四个批量请求读取存档、上报资料、读取发布榜并读取全房投递；英雄落地后只为当天尚未采集的玩家批量上报战力。
- 跨项目维护入口见 `docs/沧澜项目AI技术交接.md`。
