# 地图与运行空间

更新时间：2026-08-05

## 地图生命周期

- 地图由管理员创建，保存名称、描述和 `active`/`archived` 状态；每张地图天然对应唯一运行空间。
- 普通用户只能读取已授权地图；归档由管理员执行，保留关联数据并退出活跃运营范围。
- 永久删除与归档是独立操作，仅管理员可执行；前端连续两次确认风险，服务端仍要求请求中的地图 ID 和名称与锁定后的数据库记录完全一致。
- 永久删除在事务内写入 `map.delete` 审计并删除地图；外键级联清除权限、玩家、存档、配置、榜单、风控、礼包资格、群抽、日志和 API Key。
- 上传目录先原子改名为受控 `.deleting-map-*` 暂存目录；数据库失败时恢复，成功后同时清理暂存目录和原地图目录。启动时只重试地图已不存在的受控残留目录。
- 删除后的历史审计保留且 `map_id` 置空；已有数据库备份、上传卷快照和 OSS 副本不受影响，仍按原保留期管理。
- 地图配置以 `map_configs` 保存 JSON 配置与预加载代码，普通 JSON 配置更新需要 `map.edit` 并写审计。预加载代码具备游戏端代码执行能力，仅管理员可修改；前端以根目录平铺 `.lua` 文件，支持多文件拖入，固定保留 `main.lua` 作为入口，其他文件通过 `require("文件名.lua")` 加载。代码编辑区可在 240～960px 间上下拖动或使用方向键调整高度；编辑器延迟检查全工作区 Lua 语法、静态字符串 `require` 的文件缺失与大小写、循环依赖、动态引用和未被入口加载的文件，并在源码、文件列表和工作区状态同步标记。该检查不替代游戏客户端的最终编译与执行门禁。服务端仍读取已有虚拟目录数据，避免旧工作区不可访问，但新建与导入文件只进入根目录。旧单段代码读取时映射为 `main.lua`；存在多个文件时由服务端按路径确定性生成带缓存和循环依赖保护的模块加载器。管理员保存是预加载发布边界：同一次配置更新分别保存未改写的 `preloadWorkspace` 源码与按 Lua Token 生成的 `preloadCode` 发布产物；精简删除普通及任意等号层级的长注释和无意义空白，保留字符串、长字符串、必要 Token 间隔、UTF-8 正文及被删注释的换行数。纯空白或纯注释产物归一为空字符串；词法精简失败或精简后超过 256 KiB 时在数据库事务前拒绝发布，上一份源码和发布产物不变。虚拟文件不写入服务器上传卷；保存携带配置更新时间，过期版本返回 409，避免覆盖其他会话修改。`/api/fq/bootstrap` 只按 API Key 绑定的 `map_id` 读取并下发已持久化的 `preloadCode`，请求阶段不再次精简，空字符串表示不执行业务代码。

## 单运行空间

- FQ 不区分正式服、测试大厅或测试服；所有运行数据只按 `map_id` 隔离。
- 玩家、指标快照、自动指标会话与活跃日、日志、主播、埋点、API Key、消息、礼包资格、群抽、排行榜和风险事件均归属一张地图。
- API Key 创建时只绑定地图和权限；客户端请求体无权覆盖地图。
- 前端不提供环境切换、默认环境、环境 Badge 或跨环境复制入口。

## 运行数据清理

- 只有管理员可执行，且请求必须明确确认目标地图名称。
- 当前事务删除该地图的玩家消息、礼包资格、排行榜每日采集记录、快照与实时条目、风险事件、玩家、日志、指标快照和自动指标会话/活跃日，并将埋点触发数归零；删除自动会话会重置统计纪元。
- 当前事务保留地图、地图配置、礼物定义、排行榜定义、风控规则、主播、埋点定义、群抽活动、文件和 API Key；调整范围前必须审查外键和恢复策略。
- 操作必须写入 `map.runtime.clear` 审计记录。

## 验证

- 同一 UID 在不同地图写入后互不覆盖，同一地图的多把 Key 共享该地图运行数据。
- 普通用户不能通过替换 URL 中 `mapId` 访问未授权地图。
- 归档、永久删除、清理和配置更新分别验证权限、事务、审计与刷新后持久化。
- 永久删除验证普通用户拒绝、确认信息不匹配、重复请求、数据库回滚后的目录恢复、所有关联表清空、API Key 失效、审计保留和磁盘无残留。

主要证据：`server/routes/maps.js`、`server/routes/maps/`、`server/db/migrations/`、`src/pages/MapCenter.jsx`、`src/pages/MapWorkspace.jsx`。
