# 排行榜与风控

更新时间：2026-09-09

## 排行榜

- 上报分数范围为 `Number.MIN_SAFE_INTEGER` 到 `Number.MAX_SAFE_INTEGER`（±9,007,199,254,740,991，含边界），保持数值型协议和已有小数支持；整数可精确传输，小数仍受 Number 精度限制。任一条目越界则整批返回 400，不截断、不部分写入；数据库候选与快照继续使用 `NUMERIC(30,6)`。
- 排行榜定义按地图和稳定 `leaderboard_key` 唯一，配置名称、数值名称、升降序、分数更新模式和启用状态；Key 创建后不可修改，避免打断既有客户端接口。
- 分数更新策略有四种：`latest` 每日首份覆盖、`best` 每日首份仅更优、`realtime_latest` 每次有效上报覆盖、`realtime_best` 每次有效上报仅更优。更优按排序方向严格比较，相同成绩不替换更优策略下的分数、附属字段和达成时间；玩家名称仍随有效采集刷新。
- 每日策略按 `Asia/Shanghai` 自然日限制每个 UID 首次采集；所有策略均保留 `leaderboard_id + player_uid + collection_date` 原子去重的当日采集事实，后台移除候选不删除该事实。实时策略允许同日重报，切回每日策略仍受当天已采集状态约束。
- 客户端 `submittedTodayUids` 仅在每日策略下返回当天已采集 UID；实时策略固定返回空数组，允许客户端继续上报。实时覆盖以服务端写入顺序为准，不具备请求版本保护，迟到旧请求可能覆盖较新成绩。
- 实时条目是后台候选池，记录最近采集日期与当前有效成绩；后台实时榜排除当前地图中 `rank_ban=true` 的玩家。
- 具备排行榜管理权限的用户可从实时榜条目将对应玩家设为排行榜封禁；该操作按当前地图和 UID 写入或更新玩家的 `rank_ban=true`，不删除候选条目和每日采集事实，因此会同时从该地图所有实时榜及后续发布中排除，解除封禁后可重新显示。已发布历史快照保持不变。
- 发布接口最多创建前 100 名快照；游戏侧查询只读取最新人工发布快照的前 100 名及其中指定 UID 名次，同时返回独立保存的当日采集状态，未发布时不回退候选池。下发条目只保留界面消费的名称、分数和北京时间达成时间，指定玩家名次只保留 UID 与名次；后台候选元数据和重复原始时间不进入游戏响应。
- 发布快照在事务内复制当时符合条件的前 100 名、独立名次和成绩达成时间；后续候选更新、删除或封禁不能回写历史。
- 创建、修改、删除、发布、人工移除条目和快捷排行榜封禁均写审计。
- 实时榜支持勾选与全选当前显示条目的批量移除，最多 100 条；切换地图、榜单、搜索或快照时清空选择。只有 `leaderboards.manage` 可操作，提交必须携带 `confirm=true`，服务端锁定并核验全部条目属于当前地图与榜单，任一缺失则整批回滚；删除与批量审计在同一事务内完成。历史快照与每日采集事实保留，实时策略再次上报可重新入榜。

## 风控

- 风控规则按地图和稳定 `rule_key` 唯一，包含名称、严重级别和启用状态。
- 客户端只能按已启用规则上报；`map_id + event_key` 唯一，网络重试保持幂等。
- 事件保存上报时的规则名和严重级别快照、玩家、次数、证据 JSON、状态及处置人。
- 处置可以更新事件状态，并在同一事务内联动物品、存档、榜单封禁；玩家尚不存在时仍可保留事件，但不能伪造玩家记录。
- 规则删除使用外键定义的保留语义；历史事件仍保留上报时的规则 Key 和名称。

## 安全与验证

- 只有查看权限的普通用户不能创建榜单、发布快照、管理规则或处置事件。
- 证据 JSON 只保存处置所需结构化数据，禁止凭据、完整 Token 和无关个人信息。
- 验证北京时间每日首提、并发去重、四种更新策略、策略切换、升降序、未发布状态、最新快照切换、游戏侧读权限、封禁排除、快照不可变、三类封禁联动和审计记录。
