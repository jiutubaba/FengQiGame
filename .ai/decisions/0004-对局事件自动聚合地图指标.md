# ADR-0004：对局事件自动聚合地图指标

- 状态：已被 ADR-0005 替代
- 日期：2026-08-05

## 背景

旧 `POST /api/fq/metrics` 以地图、环境和日期整体覆盖一行快照，并发房间无法安全地逐局更新累计、在线、留存和复玩等指标。客户端也不应决定统计日期、环境或聚合公式。

## 决策

- 地图只上报对局开始、心跳和结束原始事件，请求为完整 `sessionId` 与当前有效 UID；服务端只信任 API Key 绑定的地图和环境，并使用 `Asia/Shanghai` 服务端时间。
- 后台保存幂等会话与“会话 + UID + 活跃日”事实，从第一条自动会话开始新的统计纪元，实时聚合最近 30 天的 11 项指标。
- 在线用户只统计未结束会话中 120 秒内收到心跳的去重 UID；结束事件立即清除在线状态。
- 自动会话数据存在时查询只使用自动统计；旧 `map_metrics` 和写接口继续保留为未迁移地图的快照兼容层，不与自动结果混算。
- 所有原始事实和查询继续按 `map_id + environment` 隔离，运行数据清理会同时删除该环境自动会话并重置统计纪元。

## 后果

- 并发房间只追加或幂等更新自身会话，不能整体覆盖其他房间结果。
- 客户端无需实现留存、流失或比例公式，也不能伪造日期、地图和环境。
- 统计纪元开始前没有自动趋势行，旧玩家和历史局数不会被回填。
- 未上报结束的异常房间最多影响在线状态 120 秒；历史会话与活跃日仍保留用于累计和留存计算。

## 验证方式

- 隔离 PostgreSQL 集成测试覆盖权限、三环境隔离、开始重放、跨房 UID 去重、心跳超时、正常结束、统计纪元和全部 11 项公式。
- 固定北京时间验证 D1、D7、30 日流失/回流、当日 4 局复玩和零分母。
- 地图侧纯 Lua 回归验证正式开局一次、60 秒心跳、离开过滤、结束清理、离线与非正式对局拒绝。
