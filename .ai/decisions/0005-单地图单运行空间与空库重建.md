# ADR-0005：单地图单运行空间与空库重建

- 状态：已接受
- 日期：2026-08-05
- 替代：ADR-0002、ADR-0004 中的环境边界与环境数据模型

## 背景

FQ 曾把同一地图拆为 `release`、`lobby`、`test` 三个运行环境，导致数据库唯一键、API Key、后台筛选、地图客户端配置和运营流程都需要重复维护。当前产品决定每张地图只使用一个运行空间，由 `map_id` 作为唯一租户边界。

现有三环境数据不需要迁移或兼容；本次允许直接重建正式数据库和上传卷，以空库基线恢复最小可用配置。

## 决策

- 数据库、后台 API、`/api/fq/**`、前端和地图客户端彻底删除 `environment`、`runtime_env` 及三环境兼容分支；所有业务数据只按 `map_id` 隔离。
- API Key 只绑定地图和最小权限；同一地图可以创建多把 Key，所有 Key 共享该地图运行数据。
- 迁移历史以包含现有能力的单基线重新建立，不迁移旧三环境数据，也不提供双读、默认环境或回退逻辑。
- 正式切换时停止 Compose，核验后改挂全新的 `fengqi-admin_postgres_single_data` 与 `fengqi-admin_uploads_single_data`；旧 `fengqi-admin_postgres_data`、`fengqi-admin_uploads_data` 离线保留且不再挂载。保留 `.env`、Caddy 配置和证书卷，既有 OSS 历史备份不删除也不恢复。本次按明确授权不创建新备份。
- 空库只恢复管理员、按固定顺序创建的《沧澜》《血液锦标赛2》、必要榜单/礼包定义和每张地图一把新 Key；玩家、存档、消息、资格、指标、榜单成绩、快照和审计历史保持为空。
- 自动指标继续使用对局开始、心跳和结束事件、服务端北京时间及既有聚合公式，但会话唯一边界改为 `map_id + session_id`，运行数据清理按整张地图重置统计纪元。

## 后果

- 旧地图包和旧 Key 在切换后不兼容，必须重新配置新 Key 并重新构建地图；新地图发布前收到 401 并进入既有离线降级属于维护窗口预期行为。
- 后台不再提供环境切换、默认环境、环境 Badge、跨环境榜单复制或按环境清理；运行数据清理作用于整张地图。
- 正式故障只允许向前修复新空实例，不恢复旧三环境数据。
- 旧数据库和上传卷仅作为未挂载的安全留存对象，不属于新系统回退路径；后续是否删除由人工在云主机侧单独决策。
- 玩法文案或发布流程中的“测试大厅”等名称不属于 FQ 数据环境，不受本决策约束。

## 验证方式

- 空库一次建立完整 schema，并确认不存在 FQ `environment`、`runtime_env` 字段或约束。
- 同地图多 Key 共享数据，同 UID 在不同地图互不覆盖；后台和 `/api/fq/**` 响应均不包含环境字段。
- 验证地图级运行数据清理、永久删除、存档 revision 与幂等、消息 ACK、礼包、排行榜快照、风险事件幂等和自动指标聚合。
- 正式切换后验证健康接口、容器状态、未登录 401、新 Key bootstrap、最小定义和冒烟数据清理结果。
