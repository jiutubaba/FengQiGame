# 质量与验收

## 检查层级

1. `npm run ai:docs:check`：治理文件、路径、链接、生成事实、会话上限和敏感信息。
2. `npm test`：安全工具和输入校验单元测试。
3. `npm run build`：生产前端构建。
4. `npm run audit:prod`：生产依赖漏洞审计。
5. `npm run test:integration`：隔离 PostgreSQL 全链路测试。
6. 按 `docs/上线验收清单.md` 执行部署、权限、客户端、备份恢复和浏览器验收。

`npm run check` 必须包含 AI 文档检查、单元测试和生产构建，是日常改动的最低门禁。

## 行为变更验收

- API：成功/失败格式、状态码、授权、校验、事务和审计均有证据。
- 数据：单基线可从空库一次建立且重复启动不重放；地图隔离不被破坏。
- 前端：管理员、受限用户、空状态、错误状态、桌面与窄屏均按风险比例验证。
- 任何涉及 `src/**` 前端页面、组件或样式的任务，在代码与检查完成后必须按下述约定打开免登录本地预览，定位本次变更页面并保留预览标签页；不得以构建通过代替已打开预览。
- 运维：启动、健康检查、备份和恢复不得只凭静态脚本宣称通过。

## 本地预览验收

- “打开本地预览”表示无需账号登录即可直接查看全部页面，包括公开前端、项目中心、各地图功能和管理员页面。登录页本身可供查看，但不能成为访问其他页面的前置条件。
- 以当前前端路由、菜单和功能面板为清单，逐项提供可访问入口及对应示例数据；带地图 ID、活动或问卷 Token 等参数的页面提供独立示例链接。权限和功能开关不得导致待预览页面缺失。
- 浏览器逐项检查页面可打开、示例内容可加载，菜单切换、直接访问链接和刷新均不要求登录；不得出现因缺少真实后端而产生的 502、缺失示例接口或登录重定向。后续局部改动重点复核变更页面、入口及相关导航。
- 页面持续显示“本地预览 / 示例数据”标识；写操作仅模拟或明确提示只读，不得影响真实数据。启动与隔离要求见 [免登录本地预览](operations.md#免登录本地预览)。
- 交付时保留浏览器预览标签页并给出实际可用地址；如有阻塞，明确具体原因和未覆盖页面，不得将只验证部分页面表述为全部页面通过。示例预览不等同真实认证、权限或数据库链路验收。

## 结果表述

- 已执行且通过：写明命令和结果数量。
- 已修改但未运行：明确写“已修改，未测试”。
- 受外部条件阻塞：记录条件、已完成替代验证和仍需人工完成的验收项。
- 同一问题连续失败两次后暂停，复核假设，不继续堆叠绕行方案。
